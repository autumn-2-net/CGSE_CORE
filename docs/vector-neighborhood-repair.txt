Restricted repairs for wide vector allocations (2026-10-19)
===========================================================

------------------------------

One large-multiplicity model declines before forming groups. The 40-group,

Implementation and scope
------------------------
CountVectorPartition can now admit up to 128 groups within its existing 384
variable, 2..8 bin, 2..6 dimension, capacity<=64 and preparation-work limits.
This does not widen CountAffineLattice's dense-kernel limit. Wide bins use the
new CountVectorNeighborhood candidate strategy. The complete partition and
original execution still decide whether a proposal is usable.

The strategy retains a CountLpHint session and checks its finite point before
using it. It first validates the rounded full point with exact integers. If
rounding fails, it keeps fractional coordinates free and chooses a deterministic
24-coordinate neighborhood, fixing other coordinates only inside this proposal.
The fixed terms are subtracted exactly from every original bin RHS. The existing
CountAffineLattice, kernel search and box enumeration then repair this small
model. A second 24-coordinate selection diversifies the restrictions; a final
28-coordinate selection widens the first neighborhood after both smaller
attempts fail. No recipe ID, fixture identity or known witness is consulted.

Each restored vector must satisfy every full-bin row and bound. The partition
then checks its original rows, including side conditions not used in its
decomposition. The planner independently checks the lifted primitive execution.
LP statuses, failed fixings and unsuccessful neighborhoods never establish
infeasibility, remove original choices or populate the exact residual-conflict
cache. Large signed original offsets are restored after the normalized bin
repair; they are not converted to floating point.

Scheduling, accounting and ownership
------------------------------------
Up to 32 groups retain the previous algorithm path. For 33..48 groups the new
search starts only after 3,145,728 work in that bin. An early prototype starting
at 1,048,576 found a different first allocation and made a formerly solved
40-group case slower. The final delayed opportunity preserves its ordinary
success. Above 48 groups, the restricted search can start immediately because
the former dense-vector admission did not cover those groups.

Each neighborhood has at most three 786,432-work repair attempts, with its
combined ceiling further limited to one eighth of remaining request work.
LP acquisition is bounded by 262,144 work. These are additional local ceilings
inside the existing vector and request caps, not new request credits. Preparation,
fixing, exact arithmetic, verification, LP and retained child work are charged.
Resuming an owner never renews an attempt's ceiling or restarts a finished LP.

The ordinary affine frontier stays available while a neighborhood runs; an
unsuccessful restricted search returns to it. Matching and neighborhood children
are not run concurrently. Memory reservations cover the fixed projection and
the existing children retain their own reservations. Completion, refusal,
cancellation and parent closure release all owned workspaces.

Interior follow-up
-----------------
The remaining 64-group/three-bin/three-dimensional request repeatedly reaches
an LP vertex, but none of its small restricted integer cores finishes. A vertex
keeps many coordinates at endpoints; fixing those values can leave too little
freedom for an integer completion. Refusing those cores is not a proof about
the full bin, nor about the remaining destinations.

CountVectorNeighborhood now also supports an interior hint. Starting at the
finite box midpoint, it performs at most 64 sweeps of half-space projections,
clipping each coordinate to its original bounds. One row is a retained step;
handoffs never restart a sweep. Nonfinite arithmetic declines this candidate
method. No projected inequality, floating-point point or temporary fixing is
exported as a domain fact.

The interior mode first uses fixed-seed stochastic rounding with 32 coordinates
left free, then nearest rounding with a different 28-coordinate core. It reuses
the existing retained exact affine/box repair. Both restored proposals and
rounded shortcuts must pass every original integer row and bound. The mode
retains the existing per-repair quota and overall neighborhood ceiling; the
parent still pays all work inside its original finite allowance.

Existing LP repairs run first. Only their failure opens one interior attempt
for that bin. When an interior proposal succeeds, its related residual tries
the same geometry before the LP repair; affordable exact matching keeps its
priority. A failed attempt restores the other existing paths. Changing the
destination ordering resets the preference. No case name, stored witness or
known target count is used in dispatch.

The portfolio also observes verified partial allocations followed by an admitted
interior repair. When the original completion opportunity is spent, each newly
reached residual depth can earn at most 2,097,152 further scheduling work, bounded
by the allocation's remaining local allowance and one eighth of the request's
remaining work. This changes scheduling priority, not the request or algorithm
caps. The maximum observed depth survives destination retries; pauses, repeated
observations and failed decompositions cannot replenish service. Mandatory first
visits, candidate/proof eligibility and packing/LP interleaving stay in force.
